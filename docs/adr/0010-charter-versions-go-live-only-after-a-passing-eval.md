# Charters are immutable versions that can only tighten the gate, and go live only after a passing dry run

A custom Charter can only make the gate stricter, never looser: every rule of the shipped Charter stays, and a Charter's lines may add rules or tighten through designed templates (a higher batch-match threshold, a lower intercompany tolerance, narrower Proposal kinds, an added amount cap). A Charter that let an agent do more would turn a plain-English edit into a way around the reducer gate, so loosening needs a code change and a review instead. The Charter files shipped with the agents are each role's built-in version 0. An edit is a new draft Charter version with the next number; nothing changes until the CFO publishes it, and the module refuses to publish a version unless the latest Charter eval recorded for that exact version passed as a dry run (a full close on a scratch database); a passing snapshot eval, which only replays the recorded ledger, is not enough. Publishing retires the previous live version, and retiring the live version brings the built-in Charter back. Versions are never rewritten apart from their status and who published them when, so which Charter governed an agent at any moment can always be read back. The gateway's eval runner records results under the Advisor's identity, which the agents also use; a separate evaluator identity is a follow-up.
