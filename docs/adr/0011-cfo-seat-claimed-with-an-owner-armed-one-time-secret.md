# The CFO seat is claimed with an owner-armed one-time secret

The CFO seat used to go to the first connection that asked for it, which is fine on a laptop and unsafe anywhere else. Now no connection can register itself as CFO. The database owner (the identity that published the module, in practice the seed loader calling through the spacetime CLI) arms a claim by storing only the SHA-256 of a random 144-bit Bootstrap secret with an expiry, in a table no client can read, and the loader prints a claim link that carries the secret in the URL fragment, so it never reaches a server log. Claiming hashes the secret inside the module (plain TypeScript, since reducers have no crypto library), seats the caller as CFO and deletes the claim. There is no attempt counter: a refused reducer call rolls back, so a counter could not persist, and guessing a 144-bit secret before it expires is hopeless. A database upgraded in place from a module that never recorded its owner cannot arm a claim; it keeps the CFO it already had.
